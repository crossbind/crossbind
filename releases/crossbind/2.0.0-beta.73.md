## Highlights

### One project, its apps and its web page

- `crossbind app` tells the Vite it runs that this is an app build, so a project that leaves `target.runtimeEnv` out
  builds its apps under `crossbind app` and its web page under plain Vite, from one page and one config. The web is the
  bundler plugin's own integration, not a platform of `crossbind app`.
- A web build still resolves `crossbind/app` from the app host, so code the two share bundles, and what it calls rejects
  as outside an app. `import.meta.env.CROSSBIND_APP_PLATFORM` is `undefined` there, as the app host's types now say.
- A project is an app's when it sets `target.runtimeEnv: 'app'` or lists `@crossbind/core-app-host`: `crossbind app`,
  `crossbind add` and the extensions' commands take both, and `runtimeEnv: 'app'` keeps meaning an app alone.
- The desktop-app template gains `dev:web` and `build:web`.

### Apps

- Where the package `vite` resolves to has no `vite` command, as `@voidzero-dev/vite-plus-core`, to which vite-plus maps
  `vite`, `crossbind app` runs Vite's `cli.js` beside that package's entry. Such a project no longer needs an override
  back to Vite.
- `crossbind app build` keeps in the build folder what builds for the app's other platforms wrote: the Vite plugin turns
  Vite's `emptyOutDir` off unless the project sets it, and crossbind empties the folder itself but for those apps and
  what installs them, so a Linux build no longer deletes the macOS app.
- `create-crossbind` names the desktop, Electron and Expo apps after their project's folder: `general.name` for
  desktop-app, electron-builder's `productName` and the page's title for Electron, and for Expo `app.json`'s `name`,
  `slug` and `scheme`, with one id on iOS and Android.

Reference: `docs/api/app.md`.

## Breaking changes

None.

## Migration notes

- Upgrade `crossbind`, `@crossbind/core-app-host`, `@crossbind/plugin-vite` and `@crossbind/plugin-rollup` to
  `2.0.0-beta.73` together.
- A project that sets `target.runtimeEnv: 'app'` only so that `crossbind app` builds it can leave it out, and then builds
  its web page under plain Vite as well.
- An app's build folder keeps the other platforms' apps between builds; a project that wants Vite to empty it sets
  `build.emptyOutDir` in its Vite config.

## Fixes

- An iOS app links the archive a port keeps in its xcframework alone, as `@crossbind/port-gdal-ios` does, where the
  project lists that port for several platforms; with `2.0.0-beta.72` it linked none of it.
- The dependency paths that a recipe's source replacements and a dependency rebuilt from source read take, for each
  target, the package that serves it, where several packages share a library's name.
- The READMEs of `@crossbind/example-lib-source`, `@crossbind/example-lib-cmake` and
  `@crossbind/example-lib-prebuilt-matrix` show a `crossbind.config.js` that parses as copied.
- The Expo template's Maestro flow first dismisses the dialog iOS 27 shows when `expo run:ios` opens the app through its
  link, and the Cloudflare Worker template's Playwright config takes `CROSSBIND_E2E_PORT`.

## Known limitations

- Conan packages come from ConanCenter only and have no WASI builds. An option a recipe gives no default and drops
  for a target is read as one the recipe does not have.
- The Node.js wasm `fsync` workaround reaches the operating system but does not force data to disk.
- The Windows NSIS installer downloads WebView2 when it is missing, so the Microsoft Store does
  not accept that installer.
- The Android app image's Gradle and Android build tools still carry the Guava issue tracked in
  `docs/known-issues.md`, under the existing scan exception until 15 December 2026.
