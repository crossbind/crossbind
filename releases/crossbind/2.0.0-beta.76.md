## Highlights

### An Android app runs one C++ runtime

- An Android library crossbind builds with CMake links the shared C++ runtime, `libc++_shared.so`, which the app ships
  once. The NDK's default had linked libc++ into each such library and exported it: GDAL's family carried four copies
  (GEOS, PROJ, libtiffxx and LERC, about 960 KB per ABI), and Android, which compares `type_info` by address, cannot
  match a standard exception or class across copies. A crossbind app ran on whichever copy its loader found first; a
  React Native app ran two, React Native's and the libraries', and the binding layer's `catch (const std::exception&)`
  missed an exception JSI raised inside a bound call. GDAL's recipe asked for the shared runtime through a variable the
  NDK's toolchain file does not read.
- A React Native app builds with the NDK crossbind's images build with, 30.0.16248370, or a newer one, since it ships
  that NDK's `libc++_shared.so`. The Expo config plugin sets `ndkVersion` at prebuild unless the app sets one, and the
  plugin stops a build on an older NDK, naming the version.

Reference: `docs/api/performance.md`, `docs/playbooks/integration/react-native-cli.md`.

### Every runtime a module, an addon or an app carries has its license text and version

- A wasm module's Emscripten and LLVM rows have the license texts and versions the link copies out of the web image:
  Emscripten 6.0.13 and LLVM 24.0.0git on image family 1.0.21.
- A Linux or Windows addon or app has the license and version of the LLVM C++ runtime it links, which the link copies
  out of its image: libc++ 19.1.7 on Linux, llvm-mingw's LLVM 23.1.2 on Windows. A Windows binary's mingw-w64 runtime
  has its version, 15.0.0, and its own notices alone: LLVM's license, which a Windows build listed among them, is the
  LLVM row's text.
- An Android app's `libc++_shared.so` has libc++'s license and the version of the NDK's clang, 21.0.0, and fbjni and
  androidx.webkit have their Apache-2.0 texts, as each is a file of its own in the app. `@crossbind/core-app-host`
  keeps the three texts: the NDK holds libc++'s only among its whole toolchain's.
- A vendored copy, as GDAL's giflib and libpng, has the source of the package it comes in, and GDAL's giflib its
  version, 5.2.2.
- `@crossbind/core-app-host` and `@crossbind/core-embind-napi` publish a LICENSE of their own, and `pnpm run check`
  fails on a package that would publish without one.

Reference: "Open-source licenses" in `docs/api/app.md`, section E of `ports/README.md`.

### A dead development session no longer blocks an Android release

- `crossbind app dev -p android` labels its Gradle container with its process. A container whose session ended without
  its exit hooks, as after a crash or `kill -9`, kept a Gradle daemon holding the caches every Android build shares, and
  each later release failed with "Timeout waiting to lock journal cache". The next development session or release
  removes it, and a release still timing out on that lock names the containers holding it.

Reference: `docs/api/app.md`.

## Breaking changes

- A React Native app that builds with an NDK older than 30.0.16248370 stops before its native build, naming the
  version to set.
- An Android library crossbind builds needs the app to ship `libc++_shared.so`, as a crossbind app and a React Native
  app do.

## Migration notes

- Upgrade the crossbind packages a project uses to `2.0.0-beta.76` together, its plugins, extensions and ports
  included.
- A React Native CLI app sets `ndkVersion = "30.0.16248370"` in `android/build.gradle`, as the examples do; an Expo app
  runs `expo prebuild` again, which writes it. That NDK must be installed where the app builds.
- An addon or app links again on its first build after the upgrade, which also copies its runtimes' texts and versions
  beside the build, and an Android library builds again, against the shared C++ runtime.

## Fixes

- A header of a source or CMake-source package, which only the app's C++ can include, says so when JavaScript imports
  it, in place of an empty `Tried:` list, and a prebuilt package without a build for the target names the folder it
  looked for. The lib-source and lib-cmake READMEs drop their JavaScript sections.
- The lib-prebuilt-matrix README's browser snippets await construction and calls, as a browser runs the module in a
  worker by default, and its `build:wasm` builds the browser, edge and node entries the README imports.
- The app-extension README, the extensions guide and `docs/api/extensions.md` call `initNative()` before an
  extension's function, and `crossbind/app` says a call works once the page's `initNative()` has resolved.
- `create-crossbind --help` quotes the template names that hold a space, so each line works as typed, and the error
  for a missing `package.json` names `npm create crossbind@beta`.
- `docs/api/cpp-binding-rules.md` says Node.js 26, which crossbind requires, runs JSPI by default and refuses the old
  `--experimental-wasm-jspi` flag.

## Known limitations

- `CROSSBIND_SCCACHE` caches neither a wasm build's compiles, as sccache can cache none of emscripten's, nor Rust's.
- `crossbind-licenses.json` leaves out a file a stylesheet inlines, under Vite's 4 KB `assetsInlineLimit`, and worker
  bundles; the webpack and Metro plugins do not write it.
- Conan packages come from ConanCenter only and have no WASI builds. An option a recipe gives no default and drops
  for a target is read as one the recipe does not have.
- The Node.js wasm `fsync` workaround reaches the operating system but does not force data to disk.
- The Windows NSIS installer downloads WebView2 when it is missing, so the Microsoft Store does
  not accept that installer.
- The Android app image's Gradle and Android build tools still carry the Guava issue tracked in
  `docs/known-issues.md`, under the existing scan exception until 15 December 2026.
