## Highlights

### MSIX packages and the Microsoft Store

- `@crossbind/extension-msix`, one of crossbind's own installers, writes a Windows app's MSIX package, which the
  Microsoft Store takes, signs, hosts and updates. With `app.windows.msix`, the identity Partner Center gives the app,
  it writes an unsigned package for the Store; where `app.installers` names `msix`, it writes one to hand out, signed
  with the app's certificate. Without either it writes nothing.
- The package names a full-trust app from Windows 10 1809 on, with the app's URL schemes and file types as the setup
  program registers them, an execution alias and logos from `app.icon`. Its version is the app's as `1.2.3.0`; a
  prerelease version stops the build, as the Store cannot tell it from its release.
- In an app installed from a package the updater refuses, as on a phone: Windows updates it.
- `crossbind app publish microsoft-store`, from `@crossbind/extension-microsoft-store`, builds the MSIX packages without
  the updater and hands them to Partner Center's submission API with `store/microsoft-store`'s listing, once the app's
  first submission has been made in Partner Center. `--draft` leaves the submission for Partner Center to submit and
  `--rollout` starts a gradual rollout. Its Entra ID application comes from the environment, or a publish on a terminal
  asks for it once.

### The Mac App Store

- `crossbind app publish app-store -p macos` sends a macOS app to App Store Connect as `-p ios` sends the iOS app: its
  build makes the app sandboxed and signed ad hoc, and Xcode exports it in an archive to App Store Connect, which signs
  the app and its installer package in the cloud with Xcode's account or an Admin API key. No certificate goes into the
  keychain and no profile is made by hand. `--submit` hands the version to App Review with `store/app-store`'s listing,
  whose Mac screenshots are `APP_DESKTOP`, and `--phased` releases it over 7 days.
- `@crossbind/extension-app-store` takes iOS and macOS apps alike, as App Store Connect keeps both in one record, so `-p`
  names the platform, and `crossbind app store` tells of both in one section.
- `app.macos.sandbox` runs a macOS app in the App Sandbox, with outgoing connections, the files its user picks and, with
  the microphone permission, the microphone; the publisher turns it on for its build. `app.macos.minimumVersion` raises
  the macOS release an app asks for, and the publisher's build asks for 13 at least.
- A macOS app's Info.plist takes the build number CI or a publish gives as `CFBundleVersion`, `app.encryption` as
  `ITSAppUsesNonExemptEncryption`, and `LSHandlerRank` for its document types, which App Store Connect asks for.

### A store's listing and settings in one place

- `crossbind app store [store]` tells, per store, what a publish sends, what the store would refuse of the project's
  `store/` folder and the steps only the store's website takes, each with its link, value and file. It builds nothing,
  needs no credentials and exits 1 while a store has a problem.
- A store's folder in `store/` holds its settings beside its listing languages: Google Play's contact details and Data
  safety CSV, App Store Connect's copyright, categories, age rating and App Review contact, and the Microsoft Store's
  category and notes for certification. A publish sends each one its store's API takes.
- A publish checks the listing's images against its store's sizes, formats and counts before it builds.
- For extension authors: a publisher's `guide(api)` gives its part of `crossbind app store`, `api.askHidden` asks a
  question whose answer the terminal does not show, and a publisher's `isDefault` may list the platforms it goes first
  for, as `app-store`'s `['ios']`.

Reference: "Publishing" and "The App Sandbox" in `docs/api/app.md`, `docs/api/extensions.md`.

## Breaking changes

- `crossbind app publish app-store` takes `-p ios` or `-p macos`, as it sends the macOS app too, and stops without
  either or `CROSSBIND_APP_PLATFORM`; `crossbind app publish -p ios` goes to App Store Connect as before.

## Migration notes

- Upgrade the crossbind packages a project uses to `2.0.0-beta.78` together.
- Add `-p ios` to `crossbind app publish app-store` in scripts and CI, or publish with `crossbind app publish -p ios`.
- Run `crossbind app store` before the next publish: a publish now stops before it builds on a listing image its store
  would refuse.

## Fixes

- A download a macOS app saves arrives in the folder the system gives for a file that replaces another, then moves to
  the place its user picked, instead of a hidden file beside it, which a sandboxed app may not write.

## Known limitations

- The Microsoft Store refuses the Windows setup program, which downloads WebView2 when it is missing (policy 10.2.9).
  The MSIX package is the way in, and the Store has not certified a crossbind app's package yet.
- The Mac App Store path is verified up to Xcode's signed export; no crossbind app has been uploaded, tested on
  TestFlight or through App Review on it yet. A sandboxed app opens only the files its user picks, so a dataset's
  companion files, as a Shapefile's, need picking too.
- `CROSSBIND_SCCACHE` caches neither a wasm build's compiles, as sccache can cache none of emscripten's, nor Rust's.
- `crossbind-licenses.json` leaves out a file a stylesheet inlines, under Vite's 4 KB `assetsInlineLimit`, and worker
  bundles; the webpack and Metro plugins do not write it.
- Conan packages come from ConanCenter only and have no WASI builds. An option a recipe gives no default and drops
  for a target is read as one the recipe does not have.
- The Node.js wasm `fsync` workaround reaches the operating system but does not force data to disk.
- The Android app image's Gradle and Android build tools still carry the Guava issue tracked in
  `docs/known-issues.md`, under the existing scan exception until 15 December 2026.
