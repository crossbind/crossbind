## Highlights

### One folder for this machine

- `~/.crossbind/` holds what crossbind keeps on this machine: its settings in `config.json`, which `~/.crossbind.json`
  kept, the crossbind cloud sign-in in `credentials.json`, the Android upload key in `keys/`, Android's debug key in
  `android/` and, on Windows, extensions' secrets in `secrets/`.
- What crossbind downloads or builds again, crates, Conan packages, Hermes and Gradle's caches, is in
  `~/.crossbind/cache/`, which can be deleted whenever no build runs.

### Signing in

- `crossbind login` shows a code to enter on crossbind cloud's device page, crossbind.dev/device, where you sign in
  with GitHub or with Apple. Once you approve the code there, the page shows a number that you type at the terminal,
  which gets one try.
- `crossbind usage` tells an account with no GitHub account linked the day its cloud builds open.

### An App Store Connect API key in the settings

- `crossbind config set APPLE_API_KEY` with the key's `.p8` file, `APPLE_API_ISSUER` and, where the file's name is not
  `AuthKey_` and the key's ID, `APPLE_API_KEY_ID` keep an App Store Connect API key on this machine, as Google Play's
  key and the Android upload key are kept. Each `CROSSBIND_APPLE_API_*` variable still wins.
- The key serves `crossbind app store --send`, `crossbind app release`, the stores' state, App Store Connect uploads and
  macOS notarization. The settings keep the file's full path and never the key's own text, which `config set` refuses
  without repeating it.

### For extension authors

- Contract 3: `serveOrigin(name, role, handler)` serves an origin of the app's own beside the app's, as a project's
  page, at `crossbind://name` on Apple's platforms and Linux and at `http://name.localhost` on Android and Windows.
  `Page::role()` and `Registry::function(name, roles, fn)` let its pages reach the functions that name the role, and
  nothing else of the app's. Such a page imports `crossbind/app` from `/__crossbind/app.js`, which the host answers
  with the app's own.
- `fetch(method, url, headers, done)` in `crossbind/extension.h` makes a GET or HEAD of an http or https URL through
  the system's own client, without cookies, a cache or credentials. It follows a redirect within the URL's origin, 20
  at most, gives one elsewhere back as its 3xx, and fails an answer that declares or passes 256 MiB, or takes over
  60 s, in the same words on every platform.
- `dialog.message` also shows the system's message dialog for a page of the role `project`.
- `app.android.cleartext` asks Android for plain http to any address.

## Breaking changes

- The first run of this release moves `~/.crossbind.json` to `~/.crossbind/config.json` and deletes the caches earlier
  releases kept in `~/.crossbind/` itself: `cargo`, `conan`, `conan-local`, `hermes`, `remote-index`, `rust-sysroot`,
  `sysroots` and `android/gradle`. Nothing else in the folder is touched. An earlier release on the same machine then
  finds neither its settings nor its caches.
- A `RUNNER=DOCKER_EXEC` container made before this release mounts folders that are gone: crossbind refuses it, and
  says to remove it with `docker rm -f` and make it again with the `docker run` it prints.
- `crossbind login` needs a terminal, to type the number the device page shows; with none it stops before it asks the
  cloud anything.

## Migration notes

- Upgrade every project on the machine to this release. Where one must still build with an earlier release,
  `cp ~/.crossbind/config.json ~/.crossbind.json` gives it the settings back; once it is upgraded, delete the caches it
  made again in `~/.crossbind/`.
- Edit the settings in `~/.crossbind/config.json`, or with `crossbind config set`.
- The first builds download crates, Conan packages and Hermes again, and build Conan packages from source.
- A CI cache of `~/.crossbind/hermes` takes `~/.crossbind/cache/hermes`.

## Fixes

- Windows: an app's host no longer answers a request whose query names a `.localhost` address, as
  `http://example.com/?next=http://a.localhost/`, with its own 404, and a reply goes to the document whose message it
  answers, never to a page shown since.
- Android: a form's POST toward another origin asks page-navigation, as a link does, where it went to the network
  unasked, and a page of another origin no longer gets the app's own page, with its token, from a form's POST.
- Android: under `crossbind app dev -p android`, a route's document shows in a frame of the app's page, as it does in a
  built app.
- An address with a user's name or password, as `crossbind://x@app/`, is the app's own origin to the navigation rule,
  as the webview reads it.
- `crossbind config set` takes a value that starts with a dash, which it read as an unknown option and printed whole.
