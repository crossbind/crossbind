## Highlights

### Publishing to the stores

- `crossbind app publish -p android` builds the Android app with the next versionCode Google Play takes and releases
  its bundle on a track: the internal one unless `--track` names another, out at once unless `--draft`. An app Play has
  never released takes a draft alone, which Play Console rolls out once.
- On a terminal the Android publish signs in with a Google account, through crossbind's own OAuth client with the Play
  Developer scope alone, and the system keychain keeps the sign-in. A service account
  (`CROSSBIND_GOOGLE_PLAY_SERVICE_ACCOUNT`) or its JSON key (`CROSSBIND_GOOGLE_PLAY_KEY`) set by hand still wins, and
  `CROSSBIND_GOOGLE_PLAY_TOKEN` takes an access token, as Workload Identity Federation makes one in CI with no key.
- `crossbind app publish -p ios` archives the iOS app and uploads it to App Store Connect, whose TestFlight hands it to
  testers. The archive is unsigned, then signed ad hoc with its entitlements, so it takes no development certificate,
  profile, registered device or account; the upload signs it for distribution with the account Xcode is signed in to,
  or with the App Store Connect key `CROSSBIND_APPLE_API_KEY` names, and Xcode numbers the build. Where App Store
  Connect has no app yet, the publish registers the bundle id, so the site's form for a new app lists it.
- Required reason API without its reason in an iOS app's privacy manifest stops the publish before the upload. Hermes'
  dSYM, downloaded once from Maven Central and pinned by its SHA-256, goes into the archive, and the host and the
  project's own code compile with `-g`, so crash reports show functions and lines.
- On a terminal both publishes set up what is missing as they go, such as `app.id` in `crossbind.config.js` or the
  upload key, and wait while their user does what only Play Console or App Store Connect does; in CI they name every
  missing piece at once.
- `crossbind app upload-key` makes this machine's Android upload key with the android-app image's keytool, so no JDK
  is needed, and keeps its password in the system keychain: macOS Keychain, Windows DPAPI or Linux's Secret Service.
  `--use` takes a key you have. A release build signs with it where the environment names no key.
- For CI, `CROSSBIND_APPLE_API_KEY`, `CROSSBIND_GOOGLE_PLAY_KEY` and `CROSSBIND_ANDROID_KEYSTORE` take a key's text, or
  a keystore's base64, as CI secrets come, and `CROSSBIND_APPLE_API_KEY_ID` may be left out where the key's file keeps
  the name App Store Connect gives it. The "From CI" section of `docs/api/app.md` has GitHub Actions workflows for both
  stores, which crossbind's own CI runs on main.
- `app.encryption` answers App Store Connect's export compliance question for every build, and `app.privacy` gives
  Apple's reasons for the required reason API an app calls, as its privacy manifest. `CROSSBIND_APP_BUILD_NUMBER`
  numbers an iOS build and sets an Android versionCode.
- An Android release ships its libraries stripped, its packages' shared libraries too, and keeps them as linked in the
  `-android-symbols.zip` beside its bundle, the native debug symbols Google Play takes. `app publish` uploads it with
  the bundle, so a crash in Play Console shows functions and lines.

### Development on a phone

- `crossbind app dev -p ios --device` opens an iOS app on the iPhone or iPad connected, or on the one `--device` names,
  rather than in the Simulator. Xcode signs it for the app's team, a free Apple Account's Personal Team too, and
  devicectl installs and opens it: a page edit reloads it, a native edit rebuilds and reopens it, its console shows in
  the terminal, and closing it ends the session.
- A phone on its cable reaches the dev server through the cable, with no Wi-Fi, and the dev server listens on that one
  address. The first run pairs the phone with the Mac, and names Developer Mode, a free team's trust or a bundle id
  another team holds where one of them stands in the way.

Reference: `docs/api/app.md`.

## Breaking changes

None.

## Migration notes

- Four packages move to 2.0.0-beta.68: `crossbind`, `@crossbind/plugin-vite`, `@crossbind/core-app-host` and
  `@crossbind/port-openssl`. The others stay on 2.0.0-beta.67, whose ranges take the new ones, so upgrading `crossbind`
  and `@crossbind/plugin-vite` is enough.

## Fixes

- A failed command's whole output reaches a pipe before crossbind exits. A failed link's output was cut at about
  64 KiB, before the linker's error, and on macOS none of it reached the pipe.
- The required reason API scan of an iOS build reads the archives with Xcode's `nm`, past the bitcode Rust's standard
  library embeds; a GNU `nm` on the PATH, or Xcode 26.6's, stopped the build.
- A macOS build with `CROSSBIND_APPLE_API_KEY` set and no signing identity no longer stops.
- `@crossbind/port-openssl` takes the system libraries a Windows addon links from the `libcrypto.pc` its win32 package
  ships, rather than a copy, so they follow OpenSSL's own list, as 4.1.0's bcrypt.

## Known limitations

- `app dev --device` has been run on an iPhone on iOS 27 on its cable with a paid team; a free Personal Team and a
  phone on Wi-Fi have been run by hand, not through the command. devicectl serves iOS 17 and later, and iOS 16 has not
  been tried. CI has no phones.
- `app publish -p ios` stops at TestFlight: the App Store's review and release stay App Store Connect's. Cloud signing
  with an App Store Connect key takes an Admin key.
- expat's CVE-2026-115506 and libjpeg-turbo's OSV-2026-1068 stay open in the ports. libjpeg-turbo 3.2.1, out on
  27 October, carries the record's fix commit and the three fixes the port backports; the port moves to it in a later
  release.
- In wasm, libcurl's own engine has no sockets: `curl_multi_init` returns a handle, but its transfers cannot connect.
- Developer ID signing and notarization have not been run with a real Developer ID yet, nor Windows signing with a
  cloud key service.
- On the desktop, one window. Linux, Windows and Android apps build in Docker.
- `fsync` in a Node.js wasm build reaches the operating system, not the disk.
