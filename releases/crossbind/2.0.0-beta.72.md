## Highlights

### Packages under one key

- A project declares what it takes from outside npm under `packages`, by the name its imports open with:
  `packages.cargo` holds the crates `cargo:` imports and `packages.conan` the ConanCenter packages `conan:` imports.
  The imports, `crossbind.cargo.lock` and `conan.lock` stay as they were.
- A package manager reaches a project through a new role of the extension contract, `packageSource`, which version 2
  of the contract adds: a source checks what the project declares and installs one target's packages with its own
  tool, and crossbind keeps where the tool runs, the check of everything it reports, the staging and the link. Conan
  is the first, `@crossbind/extension-conan`, which `crossbind` brings, so a project has it without installing or
  listing it. Another package manager is a package of its own.
- Misspellings that went unnoticed stop the build with what to write: a key of a Conan package's spec other than
  `version` and `options`, an option name the recipe does not have, and a name under `packages` that is neither
  `cargo` nor a package source of the project.

Reference: `docs/api/conan.md`, `docs/api/rust.md` and the Package sources section of `docs/api/extensions.md`.

### Apps

- An app's page behaves as an app's own view by default, from before its own styles and scripts: no zoom, no bounce of
  a page that fits its window, text selected and a context menu only where its user edits, no image or link dragged
  out, no tap flash, and a phone's `:hover` shown as pressed while the finger is down. A new extension,
  `@crossbind/extension-page-feel`, does it, and every app has it. Its styles lose to any rule of the app's.
- `crossbind/app` has `device`, which the host defines before the page's own scripts run: the platform and
  architecture the app is built for, its form factor (phone, tablet or desktop), the system's name and version, and
  whether a simulator or an emulator runs it. The Vite plugin sets `import.meta.env.CROSSBIND_APP_PLATFORM`.
- `app.window.titleBar: 'hidden'` lays a macOS window's page under its title bar, whose buttons stay at the top left;
  the page's own toolbar moves the window with `data-crossbind-drag`. Windows and Linux keep their title bar.
- `app.window.backgroundColor` also takes `{ light, dark }`, which iOS and Android follow from the launch screen on and
  as the system's appearance switches.
- `dialog.open` of `@crossbind/extension-dialog` shows the document picker on iOS and Android and gives copies of the
  picked files. `dialog.save` stays on the desktop.

Reference: `docs/api/app.md`.

## Breaking changes

- `conanDependencies` is `packages.conan` and `cargoDependencies` is `packages.cargo`. An old key stops the config with
  an error that names the new spelling and the config that holds the key; no alias is read.
- A crate under `packages.cargo` is text, as Cargo.toml takes it: a version, or the table that would follow the
  crate's name. An object or a number stops the config.
- A Conan package's spec takes `version` and `options` alone, and an option name its recipe does not have stops the
  build after `conan install`, with the names the recipe has. An option among the recipe's defaults that the recipe
  drops for a target is skipped there, as before.
- For code that calls crossbind's JavaScript API: `prepareConanDependencies` is `preparePackageSources`, and a staged
  dependency carries `general.packageSource` where it carried `general.conan`.

## Migration notes

Move the two declarations under `packages`:

```js
// before
cargoDependencies: { uuid: '{ version = "1", features = ["v4"] }' },
conanDependencies: { zlib: '1.3.2' },
// now
packages: {
  cargo: { uuid: '{ version = "1", features = ["v4"] }' },
  conan: { zlib: '1.3.2' },
},
```

- Upgrade the crossbind packages a project uses to `2.0.0-beta.72` together, its plugins, extensions and ports
  included: `crossbind` takes `@crossbind/extension-conan` at its own version.
- The first build after the upgrade stages each target's Conan packages again and generates every interface and
  bridge again. A React Native iOS app that uses Conan packages runs `pod install` again.
- An app that wants its page as a browser shows it lists `app.without: ['page-feel']`.

## Fixes

- A header's interface is generated again when the include path it was bound with changes; a header bound for a
  target that had no build of its dependency kept a stale interface.
- An iOS app links the archives a package keeps in an xcframework alone, as `@crossbind/port-gdal-ios` does, and that
  port declares libxml2 for iOS.
- `@crossbind/plugin-rollup` binds an app's headers for the target the build makes.
- A page's download in an Android app keeps the name the page gave it.
- `crossbind app` names the package `vite` resolves to where that package has no command.
- Under a Node.js older than 26, a missing `@crossbind/bridge-tools` names the Node.js needed and the one running.
- `create-crossbind`'s Expo template takes its versions from Expo's own template of the SDK, as `create-crossbind`
  alone has since `2.0.0-beta.71`.

## Known limitations

- Conan packages come from ConanCenter only and have no WASI builds. An option a recipe gives no default and drops
  for a target is read as one the recipe does not have.
- The Node.js wasm `fsync` workaround reaches the operating system but does not force data to disk.
- The Windows NSIS installer downloads WebView2 when it is missing, so the Microsoft Store does
  not accept that installer.
- The Android app image's Gradle and Android build tools still carry the Guava issue tracked in
  `docs/known-issues.md`, under the existing scan exception until 15 December 2026.
