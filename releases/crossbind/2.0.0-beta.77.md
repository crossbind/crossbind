## Highlights

### An executable's licenses carry every runtime it links

- A Linux or Windows executable (`-e native`) has the license text and version of the LLVM C++ runtime it links, and
  a Windows one also those of the mingw-w64 runtime, which its link copies out of its image, as an addon's and an
  app's do since 2.0.0-beta.76: libc++ 19.1.7 on Linux, llvm-mingw's LLVM 23.1.2 and mingw-w64 15.0.0 on Windows.
- A static musl executable lists the C library it carries: `crossbind licenses --platform linuxmusl -e native` adds
  musl 1.2.5 with its notice. An addon leaves the C library to the Node.js that loads it.
- `crossbind licenses` takes `-e native` for what an executable carries, as `-e node` lists an addon's and `-e app` an
  app's.
- With `-e`, `--check` fails while the list lacks the mingw-w64 runtime's or musl's notice, which their licenses ask a
  binary's distribution for, and names the binary to build first.

Reference: "Native executables" in `docs/api/native.md`, section E of `ports/README.md`.

## Breaking changes

- `crossbind licenses --check` with `-e` fails where the binary's mingw-w64 or musl notice is missing, as before the
  binary is built. Without `-e`, as for a static library's list, it checks the license fields alone.

## Migration notes

- Upgrade the crossbind packages a project uses to `2.0.0-beta.77` together.
- An executable links again on its first build after the upgrade, which copies its runtimes' texts and versions beside
  the build.
- Run `crossbind licenses --check` with `-e` after the build of the binary it lists.

## Fixes

- An executable relinks after its project is moved or copied: where CMake's cache names the old place, its build
  configures afresh, as an addon's does, instead of stopping on "CMakeCache.txt directory … is different".
- A Linux app's `.tar.gz`, which `@crossbind/extension-tar-gz` writes, carries no macOS extended attributes, so GNU
  tar unpacks it without an "Ignoring unknown extended header keyword" warning for every file.
- A binding error a caller catches no longer prints to the console. crossbind's vector coercion, which catches the one
  a JavaScript array meets and passes a vector instead, printed `Cannot pass "…" as a VectorString` on every such call
  in React Native, in an app and in a Node.js addon.

## Known limitations

- `CROSSBIND_SCCACHE` caches neither a wasm build's compiles, as sccache can cache none of emscripten's, nor Rust's.
- `crossbind-licenses.json` leaves out a file a stylesheet inlines, under Vite's 4 KB `assetsInlineLimit`, and worker
  bundles; the webpack and Metro plugins do not write it.
- Conan packages come from ConanCenter only and have no WASI builds. An option a recipe gives no default and drops
  for a target is read as one the recipe does not have.
- The Node.js wasm `fsync` workaround reaches the operating system but does not force data to disk.
- The Windows NSIS installer downloads WebView2 when it is missing, so the Microsoft Store does not accept that
  installer.
- The Android app image's Gradle and Android build tools still carry the Guava issue tracked in
  `docs/known-issues.md`, under the existing scan exception until 15 December 2026.
