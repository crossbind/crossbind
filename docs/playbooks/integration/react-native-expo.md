# Integration — React Native + Expo

> Persona 2 sub-playbook. The user's project is an Expo-managed React Native app. Detection: `expo` (or `@expo/cli`) + `react-native` in deps.

## Goal

Add crossbind to an Expo RN app so:

- iOS + Android native C++ compiles and links via Expo's prebuild system.
- Metro picks up the crossbind loader.
- Both managed-prebuild and bare workflows are supported.
- The web build (`expo start --web`, `expo export -p web`) runs the same imports as WebAssembly.

## When to use

- `expo` or `@expo/cli` in deps **and** `react-native` in deps.
- React Native 0.81 or newer: the bindings keep the JS functions passed as C callbacks in JSI runtime data, which React Native added in 0.81.
- `app.json` (or `app.config.{js,ts}`) at root.
- Bare RN (no Expo) → `docs/playbooks/integration/react-native-cli.md`.

## Workflow note: Expo Go vs prebuild

crossbind needs **native** code to ship with the app, so it requires:

- **Expo Prebuild** (`expo prebuild`) — generates `ios/` and `android/` dirs you commit (or regenerate from CI), then native libs link as in bare RN.
- **EAS Build** (`eas build`) — Expo's cloud builder; works the same as prebuild.
- **Expo Go** is **not** supported — it ships a fixed native binary; can't link new C++.

If the user is on Expo Go, you must walk them through `expo prebuild` first.

The web build needs neither: Metro compiles the C++ to WebAssembly in crossbind's Docker toolchain, as a Vite build does.

## Files involved

- `package.json`: add `@crossbind/extension-react-native`, `@crossbind/extension-react-native-ios`, `@crossbind/core-embind-jsi` (dependencies), `crossbind` (devDependency), optional `@crossbind/port-<name>`.
- `metro.config.js`: Wrap Expo's `getDefaultConfig` with `crossbind(...)`.
- `crossbind.config.{js,mjs}` *(new at root)*: Project-level crossbind config, which lists the React Native extension.
- `app.json` / `app.config.{js,ts}`: Add `"crossbind"` to `plugins`. Expo calls crossbind with its config, and the React Native extension changes the native projects `expo prebuild` makes: it also sets the app's `ndkVersion` to the NDK crossbind's Android libraries need, unless the app sets one.
- `ios/`, `android/`: Generated by `expo prebuild`; native link picks up crossbind plugin.
- `src/native/` *(if user wraps own C++)*: `.h` + `.cpp` source.

## Commands

```bash
pnpm add @crossbind/extension-react-native@beta @crossbind/extension-react-native-ios@beta @crossbind/core-embind-jsi@beta
pnpm add -D crossbind@beta     # crossbind(config) in metro.config.js, and "crossbind" among app.json's plugins
pnpm add @crossbind/port-<name>@beta     # optional

# List the React Native extension in crossbind.config.mjs, and add "crossbind" to expo.plugins in app.json, before prebuilding

# Generate / regenerate native projects from app config
pnpm expo prebuild      # idempotent; safe to re-run

# iOS pods
cd ios && pod install && cd ..

# Run
pnpm expo run:android
pnpm expo run:ios

# Web: the dev server builds the wasm on the first page load
pnpm expo start --web

# Web export: the release wasm lands next to the exported bundle
pnpm expo export -p web --clear
```

For EAS:

```bash
pnpm eas build --platform ios
pnpm eas build --platform android
```

EAS picks up `expo prebuild` artifacts automatically; crossbind's changes kick in via the regenerated `Podfile` / `build.gradle`.

## Reference config

Mirror `examples/mobile-reactnative-expo/`.

`metro.config.js` (canonical for Expo):

```js
const { getDefaultConfig } = require('expo/metro-config');
const crossbind = require('crossbind');

module.exports = crossbind(getDefaultConfig(__dirname));
```

`crossbind.config.mjs`:

```js
import Matrix from '@crossbind/example-lib-prebuilt-matrix/crossbind.config.js';
import reactNative from '@crossbind/extension-react-native/crossbind.extension.js';

export default {
    dependencies: [
        Matrix,
    ],
    extensions: [
        reactNative(),
    ],
    paths: {
        config: import.meta.url,
    },
};
```

`app.json`:

```json
{ "expo": { "plugins": ["crossbind"] } }
```

## Web

The web bundle loads the browser build a Vite or webpack build makes: wasm32, single-threaded unless
`crossbind.config.js` or one of its dependencies sets `target.runtime: 'mt'`. Expo's own commands build it: crossbind adds
no step.

- In an app with `react-native-web`, which Expo's web needs, `crossbind(config)` stages the Conan packages and builds the cargo dependencies the web build needs before it hands Metro the config. Metro resolves a `conan:` import against the files it found at startup, so the staging cannot wait for the first page.
- `expo start --web`: the dev server builds the wasm (debug) when the page first asks for `crossbind.js`, and serves `crossbind.js`, `crossbind.wasm` and `crossbind.data.txt`. The build runs inside the dev server, so a cold one holds up every client of that server until it ends. Metro does not watch the C++ sources: after an edit, reload the page, and its request for `crossbind.js` rebuilds what changed.
- `expo export -p web`: the export writes the files Metro's serializer hands it, and crossbind links the release wasm there, once every module has transformed, and adds `crossbind.js`, `crossbind.wasm` and `crossbind.data.txt` to them. Give the export `--clear`: it re-runs the `.h` transforms that write the bridges, which a warm Metro cache skips. With `web.output: 'server'`, they land among the client's files, in `dist/client`.
- `experiments.baseUrl` is honoured: the bundle asks for the files under it.

## Multithread → COOP/COEP

**Not applicable for native RN.** RN runs JS on Hermes/JSC; multithread (`runtime: 'mt'`) uses pthreads via JSI. No browser headers required.

On the web, `runtime: 'mt'` needs a cross-origin isolated page:

- The dev server sends `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp` itself, on every response.
- The production host must send them too (see `docs/playbooks/integration/vite.md`); a host that cannot set headers cannot serve a multithreaded build.
- Both headers reach the whole app: COOP `same-origin` severs the opener link that popup sign-in flows use, and COEP `require-corp` blocks cross-origin images and fonts served without `Cross-Origin-Resource-Policy`. This is why the web build stays single-threaded unless asked.
- The native builds are multithreaded either way; setting `target.runtime: 'mt'` is what makes the web build multithreaded too.

## Validation

- [ ] `pnpm install` succeeds.
- [ ] `pnpm expo prebuild` generates `ios/` and `android/` without errors.
- [ ] `cd ios && pod install` succeeds.
- [ ] `pnpm expo run:ios` and `pnpm expo run:android` build + launch.
- [ ] App calls into C++: `import { initNative } from './native/native.h'; await initNative(); Module.fn(...)` returns expected result.
- [ ] EAS build (if used) produces a valid binary.
- [ ] `pnpm expo start --web` shows the C++ result in the browser (the first load builds the wasm).
- [ ] `pnpm expo export -p web --clear`, served as a static site, shows it too; with `runtime: 'mt'`, `self.crossOriginIsolated` is `true` there.

## Common pitfalls

- **Trying to use Expo Go.** Won't work — crossbind needs native compilation. Run `expo prebuild` first.
- **React Native older than 0.81.** The generated bridges stop compiling with errors about `facebook::jsi::UUID` or `getRuntimeData`; move to an Expo SDK that ships React Native 0.81 or newer.
- **Forgetting to re-run `expo prebuild`** after adding native deps. Stale `ios/` / `android/` won't have the plugin's hooks.
- **Mixing Expo's `expo/metro-config` with bare `@react-native/metro-config`.** Use `expo/metro-config` for Expo projects (see canonical above).
- **`package.json` has both `expo` and stale RN-cli scripts.** Clean up: `expo run:android` replaces `react-native run-android` in Expo workflow.
- **EAS managed credentials prompt blocks CI.** When automating EAS, use `EAS_NO_VCS=1` or pre-set credentials.
- **arm64e / x86_64 simulator.** `@crossbind/port-*-ios` podspecs already exclude `x86_64` for simulators. Custom packages must include the exclusion (see `react-native-cli.md` "Common pitfalls").
- **`crossbind: compressBound is not bound in the native module` after a new import.** A port's header binds the functions the app imports, and Metro binds the new one when the file is saved, without a restart. The app gets it from its next build: rebuild the iOS and Android apps, and reload the page on the web.
- **A web binding is `undefined` after `.crossbind` was deleted.** A warm Metro cache skips the `.h` transforms that write the bridges, so the wasm links without them. Restart with `expo start --web --clear`. The bridges are shared with the native builds, so a header whose declarations differ on Android needs the same restart after an Android build.
- **`'conan:<pkg>/<header>' - <pkg> is declared in packages.conan but not installed` on the web.** The config stages the web build's packages in an app with `react-native-web` alone. Install it, as Expo's web needs, then start Metro again.
- **The wasm requests 404 although the app runs.** A `server.enhanceMiddleware` set on the config after `crossbind(...)` replaces the one that serves the wasm. Set it on the config `crossbind(...)` wraps, which chains it.
- **`crossbind(...)` inside another wrapper.** It gives Metro a Promise of the config, which another wrapper cannot read as a config. Wrap the others inside it: `crossbind(withOther(getDefaultConfig(__dirname)))`.
- **TypeScript paths broken.** `crossbind.config.{js,mjs,cjs}` is JS; ensure `tsconfig.json` includes it or excludes via `allowJs: true` if you want type checking.
